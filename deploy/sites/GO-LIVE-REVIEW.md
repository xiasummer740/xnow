## 1. 主站老板视角（祥哥）

他想知道的只有三件：**赚钱吗 / 会不会亏 / 出事能不能兜。**

| 关注点 | 现状 | 证据 |
|---|---|---|
| 每站月费 | ¥99 / 30 天，开站即扣，无试用 | 空余额用户创建被拒：「余额不足：需要 ¥99.00」 |
| 站长进货价 | 代理 8 折 / 非代理原价，`sites.agent_discount` 固化在开站时刻 | 代理站 #25 `agent_discount=0.8`，单均成本 25.00；非代理 31.25 |
| 平台毛利 | 客户消费 = 站长毛利 + 平台毛利 | 密室「分站客户」页：6.19 = 3.44 + 2.75 |
| 站长会不会欠款 | 开站先扣款；到期停站；余额不足续费失败即停 | 停站实测 `stop_reason=plan` → HTTP 410 |
| 代理到期会不会带走名下站 | **不会**。只把进货价打回原价 | `停站 0 个 / 代理降级 1 个`，站点 HTTP 200 |
| 站长跑路/欠款，客户余额谁兜 | **平台不兜**：客户余额是站长欠客户的服务，停站后客户看不到也退不了 | ⚠️ 见 §7 风险 R1（未覆盖：客户侧退款申诉通道） |

**结论**：钱的口径是清楚的，且成本保护在代码层（`siteCostMultiplier = max(1, g×d)`，不允许低于 1 倍成本）。

## 2. 平台超管（管理密室）视角

### 2.1 本次新增：🏬 分站客户总览

入口：密室 tab 栏右侧「🏬 分站客户 →」，独立页面 `/admin/site-customers`。

页面给什么：

- **6 张统计卡**：客户总数 / 7 日活跃 / 客户消费 / 站长毛利（+平台毛利）/ 客户充值 / 客户余额合计
- **按分站看**：每个站的客户数、7 日活跃、订单、客户消费、站长毛利、客户余额、状态；点一行即筛选该站客户
- **客户明细**：UID / 账号 / 所属分站 / 余额 / 充值 / 订单 / 消费 / 注册 / 最后登录 / 最后下单，支持搜索、7 日活跃筛选、封禁筛选、5 种排序、分页
- **导出 CSV**：一次性 5 万行上限，给对账和离线留档用

实测（Beta，3 个分站客户）：

```
分站客户总数 3（7 天新增 3） | 7 日活跃 3 | 客户消费 ¥6.19（2 单）
站长毛利 ¥3.44（平台毛利 ¥2.75） | 客户充值 ¥76.31（4 笔） | 客户余额合计 ¥144.38
```

### 2.2 权限边界（实测）

| 身份 | 分站客户接口 | 用户列表 | CSV 导出 | 财务 |
|---|---|---|---|---|
| 匿名 | 401 | — | — | — |
| 普通用户 uid 103 | **403** | **403** | **403** | **403** |
| 站长（代理）uid 11 | **403** | — | — | — |
| 超管 uid 1 | 200 | 200 | 200 | 200 |

站长只能看到自己那 1 个站（`/api/sites` → `#25 阿相涨粉工作室`），看不到别人，也进不了密室。

### 2.3 密室其它能力（沿用，已验）

备份列表、手动快照、上传还原、物理删除、审计日志、财务、流量、配置。

## 4. 分站客户（最终消费者）视角 ★最不能出事的一环

铁律：**客户永远不能知道主站存在。** 逐页实测禁词（上游/供应商/渠道商/进货/成本价）：

| 页面 | 命中 | HTTP |
|---|---|---|
| `/`（分站首页） | 0 | 200 |
| `/services` | 0 | 200 |
| `/orders` | 0 | 200 |
| `/recharge` | 0 | 200 |
| `/login` | 0 | 200 |
| `/faq` | 0 | 200 |

分站静态壳 1448 字节，`subsites-html.mjs` 每次构建都会校验「XNOW 出现 0 次」，不达标直接构建失败 —— 这条防线写进构建流程，不靠人记。

客户能看到什么：
- 自己的站名、域名、模板配色（站长定的）
- 站长定的价格（含加价）
- 自己的余额、订单、进度
- 站长的客服/联系方式

客户看不到什么：
- 主站的任何字样、价格、入口
- 别的分站
- 平台与站长之间的成本/进货价

**风险 R1（未覆盖）**：站长停站后，**客户已充值的余额没有申诉/退款入口** —— 页面直接 410。
客户这时候只能找站长。这符合商业逻辑（钱进的是站长商户），但一旦站长失联，客户会来主站投诉。
→ 建议上线前准备一条**对外口径**（客服话术），而不是临时想。

## 7. 财务 / 对账视角

| 项目 | 口径 | 是否可查 |
|---|---|---|
| 平台营收（月费） | 每站 ¥99 × 站数 × 周期 | 密室财务 |
| 平台营收（订单差价） | `SUM(charge) - SUM(charge - site_cost)` | 密室财务 + 分站客户页「平台毛利」 |
| 站长营收 | `SUM(charge - site_cost)` | 分站客户页「站长毛利」 |
| 客户充值 | 进站长商户，**平台不计入营收** | 分站客户页单列，标注清楚 |
| 客户余额 | 站长负债，不是平台收入 | 分站客户页「客户余额合计」 |
| 退款 | 订单退款会同步回冲 `site_cost` | `siteRefund.js` |

## 8. 运维 / 灾备视角 ★本次重点补强

### 8.1 发现的真空洞

原备份包只有两样：`xnow_db.sql` + `pending_payments.json`。

**换服务器会丢：**
- 站长上传的背景图/logo（6 个文件，1.1 MB）—— 数据库里只存 `/uploads/xxx.png` 路径，图不在盘上就是白底
- 每个分站自有域名的 nginx vhost —— 丢了以后这些域名全部 404，而子域名是好的，**极难第一时间发现**

### 8.2 已修

备份包现在是四件套：`xnow_db.sql` + `pending_payments.json` + `uploads/` + `nginx-sites/`。
还原时四样各回原位（图片回 `SITE_UPLOAD_DIR`，vhost 回 `sites-enabled` 并 reload）。

实测（Beta）：

```
备份 → 成员：xnow_db.sql / pending_payments.json / uploads/(2 张) / nginx-sites/(4 个 vhost)
删除一张图 → restoreBackup → 文件回来了，数据库分站客户数仍是 3
```

### 8.3 顺手修掉的隔离泄漏

`BACKUP_DIR` 原写死 `/var/www/xnow/backups` —— **Beta 的定时备份会写进生产备份库**，
文件名靠时间戳区分，人眼根本看不出哪份是测试数据。现改为可配置，Beta 已配
`BACKUP_DIR=/var/www/xnow-beta/backups`、`SITE_UPLOAD_DIR=/var/www/xnow-beta-uploads`。
实测：Beta 备份后，生产备份目录仍是 24 份，未被污染。

### 8.4 兜底脚本

`deploy/sites/rebuild-vhosts.cjs`：按数据库 `sites` 表重建所有分站 vhost，
支持 `--dry` 预演。用途：还原的备份包没带 vhost、或没 root 权限写回时。

### 8.5 README 已同步

灾备自检从 7 条扩到 10 条：加了「站长上传的图片」「分站自有域名能开」「分站客户账号还在」。
