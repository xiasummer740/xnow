## 3. 三条"不该出现"的红线

验收时如果发现以下任一条，**优先级最高**，立刻发我：

1. 客户能看到或推算出你的进货成本
2. 分站卖得比成本低，导致**你**亏钱（系统会自动抬平到成本价，只保证不亏，但客户会觉得价格和标价不符）
3. 主站 `xnow.taikon.top` 外观/价格有任何变化

补充两条已经定好、验收时可以顺手核对的行为：

### 审计过程中发现并修掉的 3 处泄露（2026-10-24 · 五十七期）

前几轮审计漏了这三处，因为它们**不含敏感词**，但一样会暴露平台身份：

| 问题 | 后果 | 修法 |
|---|---|---|
| **右下角悬浮客服指向 `t.me/Xnow001Bot`** | 客户在站长店里点客服，直接进了平台的 Telegram 群 | 分站没填客服链接就整块不显示；填了指向站长自己的 |
| **`/vip` 页是平台「至尊代理」招代理页**（¥99/月、8 折进货、佣金翻倍）| 等于在站长店里替他拉代理，还告诉客户"站长是二级代理" | 分站上路由级屏蔽 + 侧边栏入口隐藏 + 首页 VIP 模块不渲染 |
| **公开配置接口下发 `agent_discount: 0.8`** | 客户能算出平台给代理打 8 折，进而推断站长是二级代理 | 分站不下发该字段（主站保留，主站零售价本来就公开）|

> 教训：白标审计不能只搜关键词。像「平台机器人链接」「招代理页面」这类
> **功能本身**就是平台身份的东西，搜词是搜不出来的 —— 必须逐页看功能。

### 🔴 最严重的一处：分站首页源码就是平台自己的 SEO（2026-10-24 · 五十八期）

前几轮所有审计都是「打开页面看内容」，而这次发现了更上游的问题 —— **页面源码**。

| 分站路径 | 修之前返回什么 | 现在 |
|---|---|---|
| `/` 首页源码 | `title = XNOW PRO - ...`，`og:image = https://xnow.taikon.top/og-image.png`，正文里 18 处 XNOW | `title = 社媒增长服务`，无 og:image、无 canonical、**0 处 XNOW** |
| `/vpn` | 「XNOW 全球安全节点 - 高速稳定线路」= 平台的 VPN 业务页 | **404** |
| `/finance` | 「XNOW 财务大盘预览」= 平台的财务页 | **404** |
| `/en` | 「XNOW PRO SMM Panel」= 平台英文站 | **404** |
| `/404.html` | 「404 - 页面未找到 \| XNOW」 | **404** |

**为什么致命**：站长最主要的获客方式是「把链接发出去」。链接发到微信 / Telegram /
WhatsApp 时，预览卡片读的是**源码里的 og 标签**（这些爬虫不执行 JS）——
客户还没点开，就已经看到「XNOW PRO」和平台的分享图。

**修法**：构建时额外生成一份中性入口 `dist/site.html`（同一份 JS，只是 SEO 元信息中性、
favicon 换成中性图标），分站 vhost 的默认首页与 SPA 回退都指向它；
平台自己的营销页在分站 vhost 里显式 `return 404`。JS 跑起来后由前端把
title / description / og 换成**站长自己的站名**。

主站 vhost 完全没动：`/`、`/vpn`、`/finance`、`/en` 与修之前逐字相同（XNOW 出现次数 19/16/1/15）。

### 🔴 邮件兜底路径把平台广告发进客户邮箱（2026-10-24 · 六十一期）

站长第一天不会配 SMTP，这时候邮件走平台通道 —— 原来的兜底逻辑是
「没配分站 SMTP → 用平台的模板」，于是客户收到的是：

> **XNOW PRO** … 💎 升级至尊代理，佣金翻倍 …

等于平台亲自往站长的客户邮箱里塞招商广告，还当面告诉客户"你的站长是二级代理"。

**修法**：模板选择与通道选择拆开 ——
模板看「有没有站名」（有站名就用站长品牌的中性模板），通道看「有没有分站 SMTP」。

| 场景 | 修之前 | 现在 |
|---|---|---|
| 站长已配 SMTP | 站长品牌 ✅ | 站长品牌 ✅ |
| **站长没配 SMTP（走平台通道）** | **XNOW PRO 模板 + 至尊代理广告 ❌** | 站长品牌中性模板 ✅ |
| 发件地址 | 平台邮箱（无法避免）| 平台邮箱，**已在后台明确告知站长** |

实测（假 SMTP 抓包）：正文标题「阿明涨粉工作室」、正文 XNOW 命中 0 处。
发件地址仍是平台邮箱 —— 这点做不到隐藏，所以后台的提示改成了明确说明：
「不填也能用，但发件地址会是平台的邮箱，客户点开详情能看到平台域名」。

### 布局「左一个右一个」（2026-10-24 · 六十一期，祥哥当场指出）

现象：极简/杂志版式下，Hero、热门服务居中，而「三张卖点卡」和「底部 CTA」贴在页面左边。

根因（两层叠加）：

1. `.site-section` 只设了 `max-width`，这两个区块没有 `mx-auto`（其余区块有）
2. 父级是 flex 纵向容器 —— **元素一旦有 `margin: auto`，就不再被拉伸，而是收缩到内容宽度**
   于是每个区块宽度都不一样（实测同一页里出现 896 / 656 / 268 / 326 四种宽度）

修法：所有区块统一 `width: 100% + max-width: 56rem + margin: auto`；
自带背景的色带保持整幅宽，只把内部内容对齐到同一列。

实测（1440 宽）：六个区块全部 `left=269 right=1165 width=896`，色带 `0→1434` 整幅。

## 4.6 支付回调实测（方案②：钱直接进站长账户）

不需要真商户号也能验：给自己填一组测试 key，用**与 pay.js 完全相同的算法**自签回调。

| # | 场景 | 客户看到的 / 结果 | 核对 |
|---|---|---|---|
| 1 | 站长没填商户，客户点充值 | 「本站在线充值暂未开通，请联系客服充值」 | ✅ **绝不回退平台商户**（否则钱会进你账户，违背方案②）|
| 2 | 站长填了商户，客户下单 | 收款地址 = `https://bufpay.com/api/pay/<站长自己的id>`；商品名「老张涨粉铺充值」 | ✅ 用站长的商户号、站长的站名 |
| 3 | 网关回调（签名正确）| HTTP 200 `ok`；余额 50 → 60；流水「支付宝充值 — BufPay异步回调」 | ✅ 入账金额与流水一致 |
| 4 | 回调**签名伪造** | HTTP 400 `Sign Error`；余额不变 | ✅ 伪造打不进钱 |
| 5 | **同一回调重复打两次** | 第二次也回 200（让网关别再重试），但余额**不再增加** | ✅ 幂等，不会重复入账 |

⚠️ 一个容易误解的点：客户申请充值 10 元，网关实际收 10.50（5% 手续费，满 500 免），
**入账仍然是 10.00** —— 手续费不进你的账、也不进站长的账，是支付通道收的。

## 4.7 分站自有 SMTP 实测（客户收到的验证码是站长的品牌）

同样不需要真邮箱：在服务器本地起一个假邮件服务器（`127.0.0.1:2525`），
把站长的 SMTP 指向它，然后在分站上请求一次邮箱验证码。

实测收到的那封邮件：

| 抬头 | 实际值 | 核对 |
|---|---|---|
| `MAIL FROM` | `boss@laozhang.test` | ✅ 站长自己的邮箱账号（不是平台的）|
| `RCPT TO` | `customer@test.local` | ✅ 发给客户 |
| `From` 头 | 「老张涨粉铺 验证中心」 | ✅ 站长品牌 |
| `Subject` | 【老张涨粉铺】安全身份验证 | ✅ 站长品牌 |
| 正文含 XNOW | 无 | ✅ |
| 正文含「升级至尊代理」招商 | 无 | ✅ 分站邮件不带平台广告 |
| 正文含 上游/进货 | 无 | ✅ |

结论：**站长填了自己的 SMTP，客户收到的验证码邮件就是这家店发的** ——
邮箱域名、显示名、标题全是站长的。这正是"看起来不像二道贩子"的关键一环：
客户收到 `noreply@xn.taikon.top` 的邮件和收到 `boss@laozhang.com` 的邮件，
信任度完全两回事。

⚠️ 测试方法说明：我改数据库用的是直接 SQL，绕过了接口里的"清缓存"，
所以第 5 步（清空 SMTP 后）还看到旧账号发了一封 —— 那是**配置缓存 60 秒**造成的，
不是 bug。站长在后台点保存走的是接口，会立刻清缓存、立即生效。

## 4.8 倍率边界与手动加余额实测

### 倍率能设多少：实测结果（修正后的真实下限）

| 站长填的倍率 | 结果 | 系统提示 |
|---|---|---|
| 0.5 | ❌ 拒绝 | 「定价过低：分站倍率 0.5 低于成本倍率 1.0，普通用户下单平台每单将亏损」|
| 1 | ❌ 拒绝 | 「你的代理折扣是 0.8，最低要卖 1.25 倍才不亏」|
| **1.25** | ❌ 拒绝 | 「你的进价是 2 倍（全局 2.5 × 你的折扣 0.8），卖 1.25 倍每单会亏 0.75 倍。最低请设 2 倍，建议 3.00 倍起。」|
| **1.9** | ❌ 拒绝 | 同上（会亏 0.10 倍）|
| **2** | ✅ 通过 | —（刚好不亏不赚）|
| 2.5 / 3 / 100 | ✅ 通过 | — |
| 101 | ❌ 拒绝 | 「分站倍率上限 100 倍（当前 101）」|

🔴 **这里曾经是个会让站长天天亏钱的 bug，已修。** 旧逻辑把下界算成
`1 ÷ 折扣 = 1.25`，还在提示里写"最低要卖 1.25 倍才不亏"——
但站长的真实进价是 `全局倍率 2.5 × 折扣 0.8 = 2.0 倍`。
照旧提示设 1.25 倍，他**每单倒亏 0.75 倍**，而且以为自己在赚。
现在下界按下界真实成本算（2.0 倍），提示里直接写清"你的进价是 2 倍"和"每单会亏多少"。

### 临界点 2 倍的真实下单核对

| 项目 | 数值 |
|---|---|
| 服务基础成本（上游实扣）| 0.0126 / 千 |
| 客户实付 `charge` | **0.025200** = 0.0126 × 2 ✅ 与倍率一致，**没有被后台偷偷抬高** |
| 站长被扣 `site_cost` | **0.025200** = 0.0126 × 2.5 × 0.8 ✅ |
| 站长毛利 | **0.000000** ✅ 刚好不亏 |
| 客户余额 / 站长余额 | 各 −0.025200 ✅ |
| 收益报表 `today_profit` | 0.000000（3 倍时实测为 0.0126 = 营收−成本 ✅）|

> 为什么临界点必须单独测：`orders.js` 里有一条安全网 ——「售价低于分站成本时自动抬到成本价」。
> 如果 2 倍时浮点误差让 charge 比 site_cost 小一点点，客户就会**被扣比页面标价更高的钱**。
> 实测 2 倍时 charge 与 site_cost 完全相等，安全网没有触发。

### 手动加余额（方案①兜底）

站长不填收款商户时，客户充不了值，只能找站长手动加。实测：

## 8. 自有域名 + 自动证书：全链路实测（65 期）

### 实测发现的一个真 bug（已修）
用**自有域名**建站时，原来**不会生成证书和 vhost**：`domain_status` 一直是 `none`，
线上打不开，而页面上也没有任何提示 —— 站长只会觉得"这站是坏的"。

原因：建站逻辑里只有"免费子域名"才顺手发证书，自有域名要走另一个「绑定域名」接口。
现在两种域名建站都发证书 + 写 vhost。

### 实测结果（Beta）
| 检查 | 结果 |
|---|---|
| 建站返回 | 「自有域名已配置：请把 DNS 的 A 记录指向本机，生效后点一次「修复域名」换正式证书」 |
| domain_status / cert_mode | `active` / `selfsigned` |
| 证书文件落盘 | `/etc/nginx/ssl/<域名>.crt`、`.key` ✅ |
| vhost 生成 | `sites-enabled/xnow-site-28-<域名>`，含 `ssl_certificate`、`root …/client/dist`、`try_files … /site.html` ✅ |
| 带 SNI 访问该域名 | HTTP 200，标题「社媒增长服务」（子站中性页面，**不是主站**）✅ |
| 清理 | 站、vhost、证书全删，nginx 重载，分站数回到 3 ✅ |

### 顺带修掉两处隐患
1. **证书模式判断写错了**：代码里比较 `cert.mode === 'le'`，但函数返回的是 `'letsencrypt'` ——
   结果**即使签了正式证书，界面也永远显示"自签证书，浏览器可能提示不安全"**。已改。
2. **仓库里写死了 VPS 公网 IP**（`server/src/utils/siteDomain.js` 的兜底值 + 一处注释）。
   本仓库是 PUBLIC，公网 IP 不该进源码。已改为只读环境变量 `SERVER_PUBLIC_IP`；
   未配置时不做 IP 比对，只走 TXT 令牌校验（令牌每站随机，同样能证明归属）。

### 还给站长补了"三步走"说明
原来「域名」那一块只有一个输入框 + 一个「绑定并开通」按钮，小白不知道要先去改 DNS。
现在写清楚：① 加 A 记录指向哪个地址（地址来自服务端环境变量，不写死）② 等几分钟再点绑定
③ 如果显示"临时证书"，过一会儿点「修复域名」换正式证书。并新增了「修复域名」按钮。

### 仍然差一步（需要祥哥点头）
机器上没有 ACME 客户端（`certbot`），所以现在自有域名用的是**自签证书** ——
能访问、能卖，但客户浏览器会提示"不安全"。装上 certbot 后同一条代码路径就会自动换成
Let's Encrypt 正式证书（`ensureCert` 里已是"有 certbot 就优先用它"）。
