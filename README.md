## 🛠️ 小白专属：一键裸机安装向导 (Ultimate Quick Start)

忘掉繁琐的环境配置，仅需两行命令，在全新的 **Ubuntu / Debian** 服务器上直接执行：

### 1. 克隆代码到部署目录
~~~bash
git clone https://github.com/xiasummer740/xnow.git /var/www/xnow
cd /var/www/xnow
~~~

### 2. 运行一键安装魔法
~~~bash
bash install.sh
~~~

按照屏幕提示输入您的 **网站域名** 和自定义的 **数据库密码**。随后脚本全自动执行：

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1/6 | 安装系统依赖 | apt 安装 Nginx、MySQL/MariaDB、curl 等 |
| 2/6 | Node.js 18 + PM2 | 不存在则自动安装，已安装则跳过 |
| 3/6 | 配置 MySQL | 创建数据库 xnow_db，设置密码（自动适配 mysql/mariadb 服务名） |
| 4/6 | 拉取源码 | 已有代码则 `git pull` 更新 |
| 5/6 | 构建后端 | 初始化 `.env`（保留上次 JWT），npm 安装，PM2 开机自启 |
| 6/6 | 构建前端 | npm 安装 + Vite 编译 |

然后自动配置 SSL 证书（Let's Encrypt → 自签证书降级机制）和 Nginx 站点。

> **💡 脚本可重复执行**：重跑不会丢失数据，`JWT_SECRET` 自动保留避免登录失效，旧 `.env` 自动备份。
>
> 执行完毕后会进行**健康检查**，自动校验后端 API 和 Nginx 是否正常，有问题会提示。

> **⚠️ 先分清你在做哪一种，三种不能混着做**：
>
> | 场景 | 什么时候 | 数据从哪来 | 账号从哪来 |
> |---|---|---|---|
> | **A 全新站** | 第一次上线 / 开新站 | 无（空库） | 脚本自动建 `admin` / `admin123`（见第 3 节） |
> | **B 换机灾备** | 老机器挂了 / 换机房 | 最近一次备份包 | **你原来的账号**（见第 5 节） |
> | **C 原地重跑** | 同一台机器重跑脚本 | 库里现有的 | 不动（检测到已有账号就跳过建号） |
>
> **同一台机器上不要"先做 A、再灌真实数据"** —— 两边的验证结果会互相污染，事后说不清哪个结论
> 是从哪个状态得到的。一台机器验一个场景，验完留档再清空。

### 3. 💡 首次初始化 (系统引导)

`install.sh` 跑完会**自动创建一个初始管理员**（只在 `users` 表为空时创建）：

| | |
|---|---|
| 账号 | **admin** |
| 密码 | **admin123** |

凭据同时存一份在服务器 `/root/xnow-initial-admin.txt`（600 权限），装完的提示里也会原样打印。

1.  用 `admin` / `admin123` 登录，进【管理密室】配置 SMTP、支付网关、TG 机器人等全局参数。
2.  **🔴 第一件事就是改密码**：`admin123` 是写在公开代码里的默认值，改掉之前任何知道它的人都能进你的后台。
3.  配好 SMTP 后，前台注册才能用（注册必须过邮箱验证码）。

> **想换初始密码**：`XNOW_INITIAL_ADMIN_PASS=你的密码 bash install.sh`（同样只在空库时生效）。
>
> **库里已有账号时不会创建**：脚本先数 `users` 表行数，非 0 就跳过 —— 重跑安装脚本不会动你现有的管理员。
>
> **代码里没有任何万能口令**：历史上确实存在过两个硬编码口子（万能验证码 `666888`、影子账户
> `admin/admin123` 直接签发超管令牌），2026 年初的安全加固已把它们删除（提交 `40892dac`、`c824db8b`）——
> 因为本仓库是公开的，硬编码超管口令等于把每一台"还没被认领"的实例拱手让人。现在的初始管理员是一台
> 机器上的**真实数据库账号**，不是代码后门，改掉密码即彻底失效。
>
> ⚡️ 另外一条原有规则仍然有效：系统里**一个管理员都没有**时，第一个成功注册的账号会自动成为全站管理员
> （`auth.js` 里 `realUserCount === 0` 那个分支）。所以新站装完请**当天就认领**，别放着不管。

**✅ 装完自检（全过才算装好）**

| # | 检查 | 期望 |
|---|---|---|
| 1 | `cat /root/xnow-initial-admin.txt` | 文件存在，权限 `600` |
| 2 | `SELECT COUNT(*) FROM xnow_db.users` | `1` |
| 3 | 浏览器打开 `/login`，账号 `admin` 密码 `admin123` | 进得了后台 |
| 4 | 故意输错密码 | **登不进**（确认它不是万能口令） |
| 5 | `/` `/login` `/finance` `/vpn` `/en` | 都是 `200`，且 `/finance` 显示的是它的**正常内容**、不是首页 |
| 6 | `pm2 describe xnow-backend` | `restarts 0`（不是反复崩溃重启） |

> 自检全过之后，再按上面的顺序做：**改密码 → 配 SMTP → 手动备份一次**（确认备份通道能用，
> 这是第 5 节那种灾难唯一能救命的东西）。

### 4. 🔄 数据灾备与满血复活 (Disaster Recovery)
本系统提供两种方式管理数据库：

**方式一：前端可视化控制台 (推荐)**
直接登录管理员账号，点击侧边栏的 **【数据灾备中心】**。您可以可视化地：
* 设置自动化备份频率（如 0.5 小时一次），可精准回显配置。
* 随时手动创建快照、物理删除历史快照、一键下载。
* 重装服务器后，直接上传备份包，一键还原覆盖全站数据！
  备份是**一个 `.tar.gz` 归档包**，里面装着数据库全量 + 支付补单记录（补单记录不落在任何一张表里，
  单独备份会漏掉它），还原时会自动一起放回去。历史遗留的 `.sql.gz` 快照同样支持，不用转换。

**方式二：服务器 CLI 工具 (极端情况使用)**
如果您无法登录前端，可直接在服务器终端运行：
~~~bash
bash /var/www/xnow/tools/xnow_db_manager.sh
~~~

### 5. 🔄 整机灾备：换到一台全新的服务器

**这台机器彻底没了**（宕机 / 被删 / 换机房）时的完整恢复步骤。比平时重装多带**两样东西**：
原来那把 `JWT_SECRET`，和最近一次的备份包。

~~~bash
# ① 新机器上克隆代码（先别急着跑 install.sh）
git clone https://github.com/xiasummer740/xnow.git /var/www/xnow
cd /var/www/xnow

# ② 把最近一次的备份包传上去，比如落到 /root/xnow_backup_2026_10_14_05_00_00.tar.gz
#    （平时备份会同时送到 TG 和邮箱，从那儿取；也能从【数据灾备中心】下载）

# ③ 跑安装：旧密钥 + 备份包，两个都要
XNOW_JWT_SECRET=<旧密钥> bash install.sh /root/xnow_backup_2026_10_14_05_00_00.tar.gz
~~~

装完**打开网站直接就能用** —— 不用注册、不用配置，账号密码和原来一模一样。

**✅ 恢复自检（全过才算真的恢复成功）**

| # | 检查 | 期望 |
|---|---|---|
| 1 | 逐表行数 | `users` / `orders` / `services` / `configs` / `transactions` 与老机器一致 |
| 2 | **老用户不用重登** | 拿老机器签发的旧登录凭证打 `/api/user/status` → `200`；**不喂旧密钥时必然是 `401`** |
| 3 | 你自己的账号 | 浏览器用原手机号 + 原密码 login → 进得去 |
| 4 | 签名被动过的凭证 | 必须 `401`（确认不是"什么都放行"） |
| 5 | 备份配置回显 | 【数据灾备中心】里的频率与历史快照和原来一样 |
| 6 | 支付补单记录 | `server/data/pending_payments.json` 与备份包里一致 |
| 7 | 全局配置 | 后台各项配置（支付、通知等）与原来一致 |

> 第 2 条是整件事的关键：**"老用户不用重登"不是自动的**，它完全取决于有没有把旧 `JWT_SECRET`
> 一起带过来。建议恢复完就当场验一次，别等到真出事那天才发现漏带了。

> **为什么推荐在安装时把备份包喂进去？**
> 装完其实也能从【数据灾备中心】上传还原 —— 用初始管理员 `admin` / `admin123` 登进去即可
> （2026-10-15 补上初始管理员之后，原来那道"登不进也注册不了"的死锁已经解开，见第 3 节）。
> 但安装时喂进去仍然更省事：**一步到位**，还能顺手把旧 `JWT_SECRET` 一起带上（见下）。
>
> **它只会在空库上灌**：脚本先数 `xnow_db` 里的表，已经有表就**拒绝灌入**并提示改走网页还原 ——
> 防止重跑安装脚本时把现有数据覆盖掉（这是脚本里唯一会毁数据的地方，挡死了）。
>
> **🔑 那把旧密钥从哪来？** 旧机器上 `/var/www/xnow/server/.env` 里的 `JWT_SECRET=` 那一行。
> **平时就抄一份存好**（密码管理器 / 离线笔记）—— 机器一旦挂了，它就取不到了。
>
> **为什么非带不可**：`JWT_SECRET` 是所有登录凭证的签名密钥。新机器上不喂它，安装脚本会
> 随机生成一把全新的，于是**所有已发出的登录凭证当场作废 —— 全体用户被踢下线、必须重新登录**。
> 带上原来那把，**老用户手里的登录状态依然有效，打开网站直接就能用**（前提：**域名不变**，
> 浏览器的登录状态是按域名存的，换域名等于换了门牌号，那谁也救不回来）。
>
> 装完也可以在【数据灾备中心】里核对：历史快照、自动化备份频率都应当和原来一模一样。
