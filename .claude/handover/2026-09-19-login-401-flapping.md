# 登录态反复弹窗（401 flapping）——根因复现 + 修复上线

> 详细时间线与实验数据见 `.claude/PROGRESS.md` 的 `[2026-09-19]` / `[续]` / `[续二]` 三节。
> 这里只留「下次接手必须知道」的部分。

## 一句话

祥哥报「登录状态已失效，您已超过 7 天未活跃」反复弹、**重新登录也弹、关掉重开还弹**。
根因是**缓存响应里的旧 `x-new-token` 把刚登录的新令牌覆盖掉了**。修复 = 采纳令牌前先比 `exp`，只升不降。

## 关键决策

| 决策 | 为什么 | 代价 / 副作用 |
|---|---|---|
| **按 `exp` 比大小做闸门**，而不是去堵「旧令牌从哪条路进来」 | 路径穷举不完（浏览器缓存重放 / 304 响应头合并 / 跨标签页广播）；但「服务端签发的令牌 exp 随时间递增」是恒定不变量 | 前端多了一个 JWT 解码函数；令牌被**人为签成更早的 exp** 时会被拒（正常业务不会发生） |
| **旧 bundle 文件全部保留在服务器上不删** | 祥哥开着的标签页还在按哈希名加载它们，删了直接白屏 | 服务器上堆了 10 个入口包；远古那 6 个还被 Cloudflare 缓存着 200 供着，**无 CF API 凭证，清不掉** |
| **生产 `auth.js` 临时 401 诊断先留着不撤** | 要抓祥哥**下一次** 401 做最终确认 | ⚠️ **未提交的生产漂移**，备份 `auth.js.bak-1789828066`，确认后必须还原 + 重启 pm2 |

## 踩坑记录（这次最值钱的部分）

1. **「关掉后重开还是弹」被误读成「修复没生效」。**
   实际是他 13:44 重开时拿到的 `index-CQNmdSEQ.js` 是**当时最新的包**，只是那个包还不含修复。
   → **教训：判断"修复有没有生效"之前，先证明对方跑的是哪个包。** 用 nginx 日志按 UA 捞，别猜。
   注意 SPA 的 `/api/track/visit` 是 `router.afterEach` 埋点，**不触发页面重载**，不能当成"他刚访问过"的证据。

2. **A/B 测试连假绿两次**，都栽在时序：
   - 注入开太早 → `/login` 页当场被毒 → 两个包都脏
   - 注入开了但页面不再发请求 → 注入根本没被碰到 → 两个包都"干净"
   → **教训：让被测代码真的跑到那条路径上，再谈结果。** 「没复现」多半是「没触发」，不是「不存在」。

3. **304 缓存重放假设查了半天，没能复现，就不要硬当根因。**
   curl 证明 304 上服务端会重新签一把**全新**令牌；浏览器也按规范合并了响应头。
   真正交回旧头的是**不经重新校验、直接命中缓存**的那条路。**结论：堵机制，别赌路径。**
