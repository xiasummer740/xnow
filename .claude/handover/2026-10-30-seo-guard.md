## 二、为什么这是真风险（不是假想）

SEO 的地基有三处在**我们代码之外**，任何一处被改回去，站点照样 200、日志一行都不写，
只是从此不再被搜索引擎和 AI 抓到：

| 环节 | 谁在管 | 已知的回退姿势 |
|---|---|---|
| robots.txt | 后端 `routes/seo.js` 服务端渲染 | 任何一次改动/nginx 转发调整都可能弄坏，**没人会去看** |
| CF「配置 AI 自动程序策略 · 训练」 | **Cloudflare 后台** | 2026-09-15 起 CF 对新绑域名**默认禁止训练类** → GPTBot/ClaudeBot 403 |
| CF「自动程序偏好同步」 | **Cloudflare 后台** | 开着就往前塞 167 行托管内容，把我们 37 行盖掉 |

这和 2026-10-13「备份连续 13 天静默失效」是同一副面孔：系统在报正常，链路早断了。
已经在 CF 那层踩过一次（10-29 实测 GPTBot 403），而**换域名/换账号/CF 改默认值都会再来一次**。

## 三、做了什么

| 文件 | 作用 |
|---|---|
| `server/src/utils/seoWatch.js` | 巡检本体。起服 **1 分钟后**先跑一轮（部署后立刻能在日志里看到），之后**每 30 分钟**一轮 |
| `server/src/app.js` | 挂定时器（与 `checkNginxTempDirs` / `checkNginxErrors` 同一层） |
| `scripts/seo-guard-check.mjs` | 手动跑一轮，**不推 TG**，只打印 4 项实测值 + 退出码（0 全通 / 1 有异常） |

**检查项**（每个站点 4 项，站点清单读 `.indexnow-hosts` = 主站 + 所有带域名的分站）：

1. `robots.txt` 200、**首行是 `# <host>`**、含我们的 `Content-Signal`、含自指 `Sitemap:`、行数没被灌到 80 行以上
2. **GPTBot 用真实 UA 抓首页必须 200 且 ≥500 字节**（这一条才是「门关没关」的实测，不是看开关）
3. 同上，ClaudeBot
4. `sitemap.xml` 200、是合法 `<urlset>`、地址数 ≥3

**判定纪律**：只在**状态迁移**时推 TG（好→坏、坏→好各一条），持续坏 **12 小时**提醒一次。
失败措辞刻意分开 —— 「被拦（403）」和「我方抓不到（网络失败）」是两回事，混着说会把人带去错的方向。

**开关**：`SEO_GUARD=off` 关闭；`SEO_GUARD_HOSTS=a.com,b.com` 手动指定；
`SEO_GUARD_INTERVAL_MIN` 改周期；`SEO_GUARD_VERBOSE=1` 每轮都打印实测值；
`SEO_GUARD_TEST=1` 让告警带 `[测试]` 前缀。

## 五、踩到并修掉的四个坑（前两个是我首版自己踩的，后两个在收尾同步仓库时踩的）

1. **首轮全好被算成「8 项已恢复」并推了假告警**
   —— 恢复分支只看 `r.ok`，没判「上一轮是不是坏的」。20:07:29 那轮日志里明明白白写着
   `✅ [SeoGuard] 8 项已恢复`。改成 `prev && prev.ok === false` 才算恢复。
   ⚠️ **祥哥手上那条「8 项已恢复」是假告警**，起因就是这一行。
2. **站点清单路径写死 `/var/www/xnow/.indexnow-hosts`** → Beta 也读了**生产**那份清单，
   于是两个进程会各推一遍告警（Beta 日志实锤：`已启动 … xnow.taikon.top`）。
   改成相对本文件算（`../../../.indexnow-hosts`），Beta 立刻变成「未找到，跳过」。
3. **在「跑着的代码目录」里把被 import 的文件挪走，再去 `git pull`**（收尾同步生产仓库时的险招）：
   为了快进合并，我把两个未跟踪新文件 `mv` 到 `/tmp`，结果 `pull` 因为 `app.js` 有本地改动
   **中止了**，而 `/tmp` 的副本又被我同一条命令删掉 → **磁盘上新文件没了、`app.js` 还 import 着它**。
   当时进程还活着（ESM 已加载），但**任何一次 `pm2 restart` 都会起不来**。
   正确顺序：`git checkout -- <被改的文件>` 恢复成 HEAD 版本 → `git pull --ff-only`（新文件随提交一起落地）
   → `cmp` 确认内容没变。**别对生产目录做「先挪走再合并」这种操作。**
4. **`pm2 restart --update-env` 删不掉已存在的环境变量**：我在 Beta 上用 `env -u A -u B pm2 restart --update-env`
   想还原测试用的 `SEO_GUARD_HOSTS/INTERVAL_MIN/VERBOSE`，结果三个变量原样留着（pm2 是合并，不是替换）。
   必须 `pm2 delete xnow-beta` + `pm2 start src/app.js --name xnow-beta`（cwd 不变、`PORT` 来自 `.env`）+ `pm2 save`。
   ⚠️ 副作用：**Beta 的 pm2 id 从 2 变成 3**（进程列表里看到 id 变了不要以为挂了）。

## 六、没验到的（写清楚，别让下一个人以为是验过的）

1. **CF 托管内容灌回来**那条分支（首行判定 / 行数 >80）只走了代码路径，**没有造真实样本**
   —— 要造就得把生产 robots 弄坏，没做。
2. 同理，「**坏 → 好**」的恢复告警没有真实翻转样本（首轮误报那条是同一段代码的旁证，不是正样本）。
3. **12 小时重复提醒**没等（周期太长）。
4. 只看 `SEO_GUARD=off` 之外的默认路径；`SEO_GUARD_HOSTS` 手动指定的分支只在反向对照里用过。
