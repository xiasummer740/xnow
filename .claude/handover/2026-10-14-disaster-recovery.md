## 3. 查出来的两个真问题

### 3.1 换机会把**全部用户踢下线**（已修，提交 `b2973f49`）

**根因**：`JWT_SECRET` 是所有登录凭证的签名密钥。新机器上没有 `.env`（被 gitignore 挡在
仓库外），而 `install.sh` 走上「随机生成一把」的分支 → 新密钥签不出旧 token →
**全体用户登录态当场作废，每个人都要重新登录**。指标 2 直接不达标。

**为什么以前没人发现**：`README` 里写着「重跑不会丢失数据，`JWT_SECRET` 自动保留」——
但这只在**同一台机器上重跑**成立（`if [ -f .env ]`）。换机器时 `.env` 根本不存在，那句话失效。

**修法**（`install.sh` 三级兜底）：

```
XNOW_JWT_SECRET 环境变量  >  本机遗留 .env 里的值  >  随机生成（并大声警告）
```

**验证**（4 条用例，代码块是从文件里按行范围**抽出来**跑的，不是重打一遍）：

| 用例 | 输入 | 期望 | 实测 |
|---|---|---|---|
| A 全新机器，什么都不给 | — | 随机 64 位 hex + 警告 | ✅ |
| B 给了 `XNOW_JWT_SECRET` | `abc123…` | 原样采用、不警告 | ✅ |
| C 本机有 `.env` | `.env` 里的值 | 用 `.env` 的值 | ✅ |
| D 两者都给 | 两者都有 | **命令行赢** | ✅ |

`bash -n install.sh` 语法检查通过。

### 3.2 新机器是个**死锁**，网页「一键还原」根本够不着（已修，提交 `e0b7cc93`）

`README` 原本写着「重装服务器后，直接上传备份包，一键还原覆盖全站数据！」
**这句话在真·新机器上不成立**。死锁链条：

```
要进【数据灾备中心】上传备份   →  得先是管理员
要当管理员                     →  得是第一个注册的账号（空库时自动成为 admin）
要注册                         →  得收到邮箱验证码
要发验证码                     →  得先在后台配好 SMTP
而 SMTP 配置存在数据库里，新机器的库是空的   →  💀 死锁
```

代码依据：`server/src/routes/auth.js:38`（注册强制校验验证码）、
`auth.js:148-149`（**只有发信成功才存验证码**）、
`server/src/utils/email.js:21-23`（SMTP 缺配置直接抛错）、
`server/src/app.js:103-118`（空库只播种 4 个默认配置项，**不含 SMTP**）。

**结论**：备份包明明在手上，却没有任何入口能倒进去。指标 1 不达标。

**修法**：给 `install.sh` 加一个可选参数，**装完即灌**：

```bash
XNOW_JWT_SECRET=<旧密钥> bash install.sh /path/to/xnow_backup_xxx.tar.gz
```

两个设计点（都有理由，别随手改）：

1. **灌入点选在 `.env` 写好之后、后端首次启动之前** —— 后端首次启动会跑
   `sequelize.sync({ alter: false })` 补建缺的表；先启后端就会先建出一套空表。
2. **空库闸门** —— 先数 `xnow_db` 里的表，**非空即拒绝灌入**并提示改走网页还原。
   这是整个脚本里**唯一会毁数据的地方**，必须挡死（脚本可重复执行，重跑时库里可能已有真实数据）。

**验证**（沙箱彩排，用真实生产模块 + 一次性库 `xnow_fresh_test`，跑完即 drop）：

| 用例 | 场景 | 期望 | 实测 |
|---|---|---|---|
| A | 空库 + 正常备份包 | 灌入成功 | ✅ 表数 0→12、users=4、管理员 `1/18255621695/admin` |
| B | **已有数据的库** + 正常备份包 | **拒绝灌入** | ✅ 拒绝、表数不变、canary 值仍为 42 |

生产库全程 `users=4` 未受影响。

### 3.3 死锁的**根治**：空库自动建初始管理员（2026-10-15）

3.2 只是**绕开**了死锁 —— 前提是你手上有备份包。**没有备份包的全新站**（比如要开个新站、
或者备份也一起丢了）仍然是打不开的盒子。2026-10-15 祥哥问到这一点，才查出：**本来有解，
是自己在安全加固时删掉的**。

| 提交 | 删掉了什么 |
|---|---|
| `40892dac` `fix: 安全加固 - 万能验证码/路径穿越/SSL/postMessage` | 注册的万能验证码 `if (code === '666888') return {valid:true}` |
| `c824db8b` `security: 移除硬编码超管离线口令 super-admin-offline-token` | 影子账户 `admin`/`admin123` → 直接签发超管令牌（`cb20bb3d` 引入） |

**删得对**：本仓库是 PUBLIC，硬编码超管口令等于任何"还没被认领"的实例，
谁先看到代码谁就能拿最高权限。**但删完没有补替代**，死锁就回来了。
当时的安全清单还留在 `.claude/PROGRESS.md:87-101`。

**补法（不留代码后门）**：`install.sh` 收尾时若 `users` 表为空 → 建一个**真实的数据库账号**
`admin` / `admin123`（`super_admin`，余额 99999，凭据也写到 `/root/xnow-initial-admin.txt`）。
与被删掉的影子账户的区别：

| | 被删的影子账户 | 现在的初始管理员 |
|---|---|---|
| 身份来源 | 代码里的 `if (account==='admin' && password==='admin123')` | 数据库里一行真实记录 |
| 令牌 | 返回硬编码字符串 `super-admin-offline-token`（中间件其实不认，本身是个 bug） | 走正常 `/api/login` 拿真 JWT |
| 生效范围 | 所有实例，直到出现第一个 admin | 只在该机器空库时创建一次；改密码即失效 |
| 可覆盖 | 否 | 是：`XNOW_INITIAL_ADMIN_PASS=xxx` |

**实测**（演练机 `87.83.104.229`，2026-10-15）：

- 建号语句：`users` 表的 `created_at`/`updated_at` 是 **NOT NULL 且无默认值**，必须显式写 `NOW()`。
  少写这两列会 `ERROR 1364: Field 'created_at' doesn't have a default value`
  —— 网上常见的"6 列"写法在这里一定失败（我实测踩过）。
- `POST /api/login {"phone":"admin","password":"admin123"}` → 200 + 真 JWT（169 字符）
- `/api/admin/users` → 200；`/api/user/status` → 200 `{"balance":"999999.00","role":"super_admin"}`
  （`user.js:15` 本来就有 super_admin 的特判分支 —— 说明这套设计当年就是为冷启动准备的）
- 经 nginx 再走一遍 → 200
- 脚本里那段新代码在"与真表结构相同的空表"上跑通：INSERT 成功、`created_at` 有值、
  `admin123` bcrypt 比对通过；有数据时走"跳过"分支（真库当时 5 个账号 → 一个都没动）

**⚠️ 残留风险**：默认值 `admin123` 写在公开仓库里 → 新站装完到改密码之间是敞口。
所以新站装完**当天就要登录改密码**；另外 `auth.js` 里"库为空时第一个注册者自动成为管理员"
（`realUserCount === 0`）那条规则还在，别让陌生人抢注。

## 6. ⚠️ 灾备的已知缺口（重装会退化，尚未修）

### 6.1 四个 nginx 配置是**服务器孤本**

实测 `/etc/nginx/sites-enabled/` 下有 4 个手写文件，而 `sites-available/` 里**只有
`default` 和 `xnow3`** —— 也就是说这 4 个文件**不在仓库里、也没有软链**，机器一挂就没了：

| 文件 | 作用 |
|---|---|
| `xnow-http-redirect` | 80 端口 default_server → 301 |
| `xnow-https` | `server_name 192.129.210.52`，**是另一个项目**（XNOW-Flow，上游 `:8000` + `.ipa` 静态） |
| `xnow-spa` | `listen 127.0.0.1:8080` |
| `xnow-spa-https` | **本 SaaS 站点**：`xnow.taikon.top` + CF 真实 IP 还原 + `/api/` → `:3000` |

`install.sh` 生成的是一份**功能等价**的 `sites-available/xnow`，但**不是同一份文件** ——
重装后配置能跑，但手写进生产的那 22 条 `set_real_ip_from`（CF 回源段）等增量**需要核对**。

> 📌 **仓库里已有先例规则**（`PROGRESS.md` 2026-09-20 那条）：
> 「**生产上改的东西，`install.sh` 模板必须同步补上** —— 否则以后重装又退回旧样。」
> 这条规则**只写在 PROGRESS 里，没进 `CLAUDE.md`/`specs/`**，所以容易被忽略。
> 上面这 4 个文件正是漏网之鱼。
